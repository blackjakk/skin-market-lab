# Accessibility hardening record (2026-07-26)

Goal: regular, low-vision, keyboard-only, and different-device users can all
reliably complete the core actions — read the market, sort, open an item,
switch chart ranges, manage portfolio lots, search, verify fixings, read the
backtest. This file records what was found, what was fixed, how it is proven,
and what risk remains. The standing reviewer checklist lives in
`.claude/skills/accessibility-review/SKILL.md`; the regression gate is
`npm run probe:a11y` (`tools/a11y-probe.js`, in CI).

## Method

Three independent read-only audits against the live app (real Chromium, real
key events, WCAG 2.1 contrast math on computed styles): responsive/multi-device
(6 paths × desktop/tablet/phone + 200% zoom), keyboard/focus (full Tab walks,
core-flow completion), semantics/contrast (measured ratios + live-DOM ARIA).
43 raw findings deduped into one fix spec with a frozen cross-file contract,
implemented by three parallel fix lanes on disjoint file sets (CSS/HTML ·
skins.js · gate), then integrated, gated, and re-validated end-to-end as four
personas (mouse, keyboard-only, phone touch, 200%-zoom low vision).

## Issues found → fixes shipped

Severity at audit: 3 BLOCKER-class defects, 18 MAJOR, 22 MINOR (43 findings,
overlapping). The deduped defect list:

| Defect | What was wrong (measured) | Fix |
|---|---|---|
| Mobile layout lock | Home layout dictated its own 873px width on ANY viewport ≤900 (phone rendered ~45% zoomed out; row taps failed hit-testing; 1219px on 1000px desktop windows; both 200%-zoom modes broken). | Invisible focus | `tr.mrow` and `.sr-row` had `outline:none` + a 1.09:1 background swap identical to hover — 64+ tab stops with no visible focus; `#searchBox` had only a 1px border swap. | 2px `var(--ds-focus)` rings on `:focus-visible` (bg swap kept for hover only). |

## Proof

- `tools/a11y-probe.js` — 34 hermetic real-Chromium checks encoding the fixed
  end-state (viewport sweeps, tap hit-test, ring measurements under real Tab,
  keyboard sort, modal trap/restore, stale-Enter, WCAG contrast on computed
  styles, coarse-pointer heights, ARIA batch, skip link, focus restore, zero
  page errors). On the pre-fix tree it failed 28/34 — reproducing the audit
  numbers bit-for-bit — and passed the 6 known-good guards; on the fixed tree
  it is 34/34. Runs twice byte-identical; ~15s; wired into `gates.yml`.
- Full existing battery green and UNMODIFIED on the integrated tree:
  `probe.js` 133, `client-probe.js` 39, `ds-guard` exit 0 (debt 20 == baseline),
  `ds-component-test` 77 (5 new specTable checks).
- Fix-lane batteries: 50-check visual battery (before/after measurements per
  defect), 48-check real-key interaction battery (ran green twice), both
  archived in the session records.
- Four-persona end-to-end validation on the merged tree (mouse desktop,
  keyboard-only, phone touch, 200% zoom): PASS — all core actions completable
  by all four personas; keyboard walk of 31 stops with zero missing rings and
  zero focus landings on `<body>`; no horizontal scroll anywhere at
  390/680/768/1360 or under 2× zoom; zero page errors. It surfaced three
  minors the gates missed, all fixed post-validation: the skip link landed 21
  stops before the table (retargeted to `#mktPanel`), the portfolio ✕ was the
  one control on the UA ring (house 2px ring added), and sort headers /
  search options sat just under the wave's own 32px coarse floor (padded).

## Residual risks / known limitations

- **Chart crosshair is mouse-only.** Per-day values for keyboard/SR users come
  from the range-sized data tables instead (and index levels from the new home
  table). A focusable-canvas arrow-key crosshair is possible future work.
- **Market rows are 64 individual tab stops.** Roving tabindex was deliberately
  deferred: the probe contract freezes `tabindex="0"` on every `.mrow`. The
  skip link (+ the sort buttons living before the table) is the mitigation.
  Revisit if the row contract is ever renegotiated.
- **Row semantics are pragmatic, not ideal.** `tr[tabindex]` + aria-label +
  Enter/Space works, but a link-in-name-cell pattern would be cleaner ARIA;
  also frozen-contract-bound.
- **Live-tracker-only paths** (snapshot/bootstrap buttons, import-success
  focus re-land on `#importBtn`) are code-reviewed but not browser-proven in
  static CI; static mode has no import button, so the gate drives the modal
  via `window.openImport`.
- **`#apiAddr` border token rides an `!important`** (the input is inline-styled
  in skins.js); fold the inline style into the stylesheet to drop it.
- **Inline prose links on doc pages** stay under 24px on touch — exempt under
  WCAG 2.5.8 (target-in-text), noted for completeness.
- **`prefers-reduced-motion`** remains trivially satisfied (zero CSS
  animations/transitions); keep it that way or add the media query with the
  first animation.
- **Probe-authoring trap (measured during validation):** on this
  Playwright/Chromium, `page.screenshot({fullPage:true})` permanently kills
  `pointer: coarse` emulation for the page — touch-target metrics measured
  after a fullPage shot read the desktop values. Measure targets BEFORE any
  fullPage screenshot (the a11y probe does).
